# 0.4.1 — 2026-11-15

## Added

- **On-view status and venue** ([#74](https://github.com/cyanheads/smithsonian-mcp-server/issues/74)): `smithsonian_get_object` returns `on_view` (absent when the record carries no flag) and `current_exhibitions[]` (`building`, `room`, `title`), and `smithsonian_search_objects` takes `filters.on_view_only`. The mirror stores the on-view subset and serves the filter; a shard not yet re-read after the schema upgrade is answered live.
- **`indexed` on `smithsonian_get_object`** ([#73](https://github.com/cyanheads/smithsonian-mcp-server/issues/73)): the record's indexed `name`, `place`, `object_type`, `date`, and `topic` values, each usable verbatim as the matching search filter.
- **`unit_code` on `smithsonian_find_related`** ([#75](https://github.com/cyanheads/smithsonian-mcp-server/issues/75)): scopes every signal to one museum, and a no-match result inside the scope says so.
- **`start` and `limit` on `smithsonian_get_media`** ([#76](https://github.com/cyanheads/smithsonian-mcp-server/issues/76)): pages a record's CC0 images in catalog order (`limit` capped at 1,000, a larger value served at the cap with a notice) and returns `cc0_image_count`.
- **`mirror:*` CLI exit 75** when another process's sync holds the store (`sync_locked`); the scheduled refresh treats it as a skipped tick.

## Changed

- **One deadline per tool call** ([#68](https://github.com/cyanheads/smithsonian-mcp-server/issues/68)): `CALL_DEADLINE_MS` (50 s) replaces the per-read retry deadline, so chained reads can no longer outlast a client's 60 s request timeout. A call that runs out gets `Timeout`; `smithsonian_find_related` returns its partial results naming the timed-out signals, and the `invalid_filter` and `invalid_category` recovery lookups run on the time left.
- **`structuredContent.notice` is raw text.** It used to carry Markdown backslash escapes; `content[]` now escapes it when rendering.
- **Summary `thumbnail_url`** is the small "Thumbnail Image" rendition. On IDS-hosted records it used to be the full-size delivery URL.
- **`alt_text` and `description`:** empty values are omitted.
- **`content[]` rendering** ([#70](https://github.com/cyanheads/smithsonian-mcp-server/issues/70)): links and images render as such, multi-value fields render one list item per value, and headings and the notice trailer are encoded so the Markdown reads back as the data.
- **`smithsonian_find_related`** sends its period and object-type filters in `smithsonian_search_objects` order, so a continuation reuses the cached search.
- **Mirror schema v2**: shard ETags are nulled on migration and a `shards_etag` index is added. The server logs the pending re-read at startup.

## Fixed

- **`toPlainText`** strips only `a b br em i p span sub sup`; other `<…>` catalog text is kept, and stripping is linear in the input ([#70](https://github.com/cyanheads/smithsonian-mcp-server/issues/70)).
- **`smithsonian_get_media`** falls back to the full-size image URL when an image has no JPEG resource ([#71](https://github.com/cyanheads/smithsonian-mcp-server/issues/71)).
- **`smithsonian_list_terms`** no longer caches a malformed `/terms` response as an empty vocabulary for the full TTL, and a lookup that could not complete yields hints that claim no membership ([#72](https://github.com/cyanheads/smithsonian-mcp-server/issues/72)). A term named like an `Object.prototype` member (`constructor`) renders correctly.
- **`api_key_rejected`** (`Forbidden`) is declared on all six tools.
- **Mirror refresh** no longer spawns a child process after shutdown has begun.
