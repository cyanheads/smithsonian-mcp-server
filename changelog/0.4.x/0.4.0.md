# 0.4.0 — 2026-11-01

## Added

- **Published guide skill**: `skill://smithsonian-guide/SKILL.md` serves workflows and gates for the `smithsonian_*` tools through the new `skill://{+path}` resource template and is listed in `resources/list`.
- **Open Access mirror** ([#66](https://github.com/cyanheads/smithsonian-mcp-server/issues/66)): an optional local copy of the Smithsonian Open Access bulk metadata, enabled by `SMITHSONIAN_MIRROR_PATH` and off by default. `bun run mirror:init`, `mirror:refresh`, and `mirror:status` build and maintain it; the full store is about 17 GB. Bun uses its built-in SQLite; Node needs the optional peer `better-sqlite3`.
- **Mirror routing**: when configured, the mirror serves record reads and filter-only searches and browse pages within its 100,000-index-entry scan budget; everything else goes to EDAN. Responses then carry `sources` and `mirror_snapshot` enrichment, and mirror pages run in mirror order.
- **`SMITHSONIAN_MIRROR_REFRESH_CRON`** (default `0 12 * * *`, empty disables) refreshes the mirror in a child process on HTTP. Only `mirror:init` starts a build: a refresh of a store holding nothing fails (`mirror_not_built`) before any request, and a server whose store has no completed build logs a warning naming `SMITHSONIAN_MIRROR_PATH` and answers live. A file that isn't a SQLite store fails startup with a `ConfigurationError` naming the variable.
- **Response cache** ([#65](https://github.com/cyanheads/smithsonian-mcp-server/issues/65)): each server instance caches successful search and content responses in memory, bounded at 64 MiB. TTLs are `SMITHSONIAN_SEARCH_CACHE_TTL_SECONDS` (default 3600) and `SMITHSONIAN_CONTENT_CACHE_TTL_SECONDS` (default 86400); concurrent identical requests share one upstream call.

## Changed

- **Page-size caps** ([#63](https://github.com/cyanheads/smithsonian-mcp-server/issues/63)): search `rows`, browse `rows`, and find_related `limit` rise to 1,000 (EDAN's `/search` maximum, from 100, 50, and 20) and list_terms `rows` to 40,000 (from 100). A larger value is served at the cap with a notice opening "rows 1500 exceeds the cap of 1000; the page was served with rows 1000.", and paging notices name the next `start`. `SMITHSONIAN_CLAMP_LIMITS=false` rejects over-cap values and advertises each cap as the schema `maximum`.
- **Descriptions and instructions**: search `query` states that every word is required, `OR` does not widen a search, and `NOT` excludes. `filters.place` and `filters.scientific_name` gain worked examples, browse `sample_objects` notes mirror order, and server `instructions` add the rate posture and point at the guide skill.
- **Framework rendering** (mcp-ts-core ^0.13.18): tool error text in `content[]` gains Markdown escapes ([cyanheads/mcp-ts-core#760](https://github.com/cyanheads/mcp-ts-core/issues/760)), every line of a multi-line enrichment notice stays inside the trailer quote ([cyanheads/mcp-ts-core#765](https://github.com/cyanheads/mcp-ts-core/issues/765)), trailer string values render as code literals ([cyanheads/mcp-ts-core#785](https://github.com/cyanheads/mcp-ts-core/issues/785)), and `escapeMarkdownInline` escapes a trailing ` #` ([cyanheads/mcp-ts-core#781](https://github.com/cyanheads/mcp-ts-core/issues/781)).
- **Framework runtime** (mcp-ts-core ^0.13.18): out-of-range framework config fails startup naming the variable ([cyanheads/mcp-ts-core#747](https://github.com/cyanheads/mcp-ts-core/issues/747), [cyanheads/mcp-ts-core#746](https://github.com/cyanheads/mcp-ts-core/issues/746)), a handler that returns after its request was cancelled settles as `RequestCancelled` `-32011` ([cyanheads/mcp-ts-core#753](https://github.com/cyanheads/mcp-ts-core/issues/753)), HTTP shutdown answers 503 while draining and no longer waits the full drain with a request in flight ([cyanheads/mcp-ts-core#749](https://github.com/cyanheads/mcp-ts-core/issues/749), [cyanheads/mcp-ts-core#757](https://github.com/cyanheads/mcp-ts-core/issues/757)), and log redaction matches secret names run into another word ([cyanheads/mcp-ts-core#702](https://github.com/cyanheads/mcp-ts-core/issues/702)).

## Fixed

- **`smithsonian_search_objects` `filters`** reject unknown keys with `-32602`, naming `filters.<key>` and the accepted keys, before any upstream request; a key outside the set used to be stripped and the search ran wider than asked ([#61](https://github.com/cyanheads/smithsonian-mcp-server/issues/61)).
- **Non-image media**: `smithsonian_get_object` carries `media_summary.non_image_media[]`, one `{ type, url?, is_cc0 }` per media item whose type isn't `Images` (3D viewers, scanned books, slideshows, PDFs), rendered as `[type](url)` links. The `no_images` recovery on `smithsonian_get_media` points there instead of `record_link` ([#62](https://github.com/cyanheads/smithsonian-mcp-server/issues/62)).
- **`unit_code` on `OCIO_DPO3D` records** is the indexed code, which filters and browses to them, instead of `SAO`, `NMNHANTHRO`, and other record-level codes; `museum_name` follows. Optional `holding_museum_name` names the holding unit from the record's `data_source` when the two differ, resolving a `data_source` that is itself a unit code (`SERC`) to that unit's name, on search rows, find_related rows, and `smithsonian_get_object` ([#64](https://github.com/cyanheads/smithsonian-mcp-server/issues/64)).
- **Blank-query `invalid_filter`**: a blank `query` with an unmatched `unit_code` or `object_type` no longer re-queries EDAN with an empty `q` for suggestions. That request drew an HTTP 400 logged at error level; the result and hint are unchanged ([#67](https://github.com/cyanheads/smithsonian-mcp-server/issues/67)).
- **Request retry deadline**: every attempt and backoff of an EDAN read shares one 50 s deadline, down from up to about 74 s, and a cancelled call ends its backoff wait at once instead of sleeping it out. The 15 s per-attempt timeout is unchanged.
