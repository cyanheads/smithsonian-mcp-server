# 0.5.0 — 2026-11-26

## Added

- **`sets` on `smithsonian_get_object`** ([#81](https://github.com/cyanheads/smithsonian-mcp-server/issues/81)): the catalog's set names, each under its own label (`See more items in`, `On View`, `Location`, `Exhibition`), in catalog order; `[]` when the record lists none.
- **`smithsonian_get_media` `media: "3d"`** ([#83](https://github.com/cyanheads/smithsonian-mcp-server/issues/83)): returns `models[]`, each CC0 3D package's viewer URL, thumbnail, and downloadable `files[]`, with `cc0_model_count`. A record with no package fails `no_models`, and `not_cc0` applies to packages. The images-mode `no_images` hint names the 3D call, and the recovery hints name complete, runnable search calls; the `no_models` hint routes only to a call that would deliver.
- **`record_id` accepted as an alias of `id`** ([#84](https://github.com/cyanheads/smithsonian-mcp-server/issues/84)) on `smithsonian_get_object`, `smithsonian_get_media`, and `smithsonian_find_related`; sending both is rejected.

## Changed

- **`smithsonian_get_object` replaces `materials` and `dimensions` with `physical_description`, every catalog physical-description entry under its own label, in catalog order** ([#79](https://github.com/cyanheads/smithsonian-mcp-server/issues/79)).
- **Concurrent cold reads of one vocabulary field share one `/terms` request per tenant and field** ([#77](https://github.com/cyanheads/smithsonian-mcp-server/issues/77)); `SMITHSONIAN_TERMS_CACHE_TTL_SECONDS=0` turns sharing off with the cache. A cold read whose caller cancels or runs out of time now rejects as `RequestCancelled`, or `Timeout` with reason `retry_deadline_exceeded`, in the response cache's wording.
- **Mirror schema v3** ([#81](https://github.com/cyanheads/smithsonian-mcp-server/issues/81), [#82](https://github.com/cyanheads/smithsonian-mcp-server/issues/82), [#83](https://github.com/cyanheads/smithsonian-mcp-server/issues/83)): the mirror stores `setName`, `objectRight`, and the 3D package file keys. The first open of an older store re-reads every shard, and until that refresh lands, record reads and `on_view` searches go to the live API.

## Fixed

- **Museum-name lookup in `smithsonian_list_terms`** ([#80](https://github.com/cyanheads/smithsonian-mcp-server/issues/80)), the lookup `smithsonian_browse_category`'s museum-mode recovery names, reaches NMNH's divisions and the Freer/Sackler and Cooper-Hewitt names, and ignores case, extra whitespace, a leading "Smithsonian", `&` versus "and", curly versus straight apostrophes, and hyphens versus spaces. `smithsonian_browse_category` still takes an exact unit code. `museum_name` and `labels` output is unchanged; matches only widen.
- **`object_rights`** ([#82](https://github.com/cyanheads/smithsonian-mcp-server/issues/82)) joins every rights statement, SIA's `objectRight` included.
- **`smithsonian_get_media` `not_cc0` recovery in images mode** names a complete `smithsonian_search_objects { query: "", filters: { cc0_only: true } }` call; the previous one failed as written.
