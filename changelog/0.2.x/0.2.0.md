# 0.2.0 — 2026-07-25

## Changed

- **Breaking: tool renames** — `smithsonian_search` → `smithsonian_search_objects`, `smithsonian_explore` → `smithsonian_browse_category`. No compatibility aliases; `tools/list` exposes only the new names. Migration: replace any `smithsonian_search` call with `smithsonian_search_objects`, and any `smithsonian_explore` call with `smithsonian_browse_category`. ([#31](https://github.com/cyanheads/smithsonian-mcp-server/issues/31))
- **`smithsonian_browse_category` zero-match contract** — a category browse that matches nothing now throws `invalid_category` (ValidationError) instead of `no_results` (NotFound), with a mode-specific recovery hint naming the literal next call (`smithsonian_list_terms` for museum/culture/period; harvested `object_type` candidates from a free-text re-query for medium). A `start` past the end of a real category still returns a successful empty page. ([#31](https://github.com/cyanheads/smithsonian-mcp-server/issues/31))
- **`period` mode requires `NNNNs` decade format** — validated on the input object rather than a per-field regex, since `value` is polymorphic across the four modes; malformed values (`"1940"`, `"40s"`, `"1940S"`) are rejected at the schema boundary instead of reaching upstream as a guaranteed-zero query. ([#31](https://github.com/cyanheads/smithsonian-mcp-server/issues/31))
- **Server instructions** — replaced with the ordered workflow: `smithsonian_search_objects` → `smithsonian_list_terms` → `smithsonian_browse_category` → object/media/related lookups by `record_id`.

## Fixed

- **`smithsonian_search_objects` `unit_code` filter** — now quoted through the same `luceneField()` helper as its sibling filters. Previously interpolated unquoted into the Lucene query, so a multi-word value (e.g. a museum name passed instead of a unit code) leaked its trailing words into free text and returned a silently unfiltered result set reported as the museum's total. ([#32](https://github.com/cyanheads/smithsonian-mcp-server/issues/32))

## Dependencies

- `@biomejs/biome` `^2.5.4 → ^2.5.5`
