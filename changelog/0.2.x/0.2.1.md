# 0.2.1 — 2026-07-25

## Added

- **`SMITHSONIAN_TERMS_CACHE_TTL_SECONDS`** — caches each field's term vocabulary in the injected `StorageService` (default `3600`, `0` disables). Upstream `/terms/{field}` ignores paging and always returns the full set — `place` alone is ~114k terms / 3.2 MB — so every uncached `smithsonian_list_terms` call re-downloaded it. ([#38](https://github.com/cyanheads/smithsonian-mcp-server/issues/38))
- **`smithsonian_list_terms` `labels`** — `unit_code` terms now come back with an optional `labels` map of museum names (`MUSEUM_NAMES`, now exported), and `contains` matches the label as well as the code — `"National Air and Space"` resolves to `NASM` in one call. ([#37](https://github.com/cyanheads/smithsonian-mcp-server/issues/37))
- **`SmithsonianService.isIndexedTerm()`** — exact, case-sensitive vocabulary-membership check, reading the cached vocabulary from the change above.

## Changed

- **`invalid_category` / `invalid_filter` recovery hints** — `smithsonian_browse_category` (museum/culture/period) and `smithsonian_search_objects` (culture/place/date_decade) now check the failing value against its indexed vocabulary before naming a fix. A value outside the vocabulary still routes to `smithsonian_list_terms`; a value the index enumerates but that matches no retrievable object — 14 of the 48 `unit_code` terms and a long tail of `culture` terms are in this state — is named as indexed-but-empty and routed to a different term or a `smithsonian_search_objects` free-text query, instead of looping the caller back to `smithsonian_list_terms` and the identical value. ([#33](https://github.com/cyanheads/smithsonian-mcp-server/issues/33))
