# 0.1.14 — 2026-07-10

## Added

- **`smithsonian_list_terms` `contains`** — optional case-insensitive substring filter over the term vocabulary, applied in-process on the already-fetched terms before pagination, so `total` reflects the post-filter match count. Resolves a guessed value (e.g. `greek`) to its exact controlled-vocabulary term(s) in one call. ([#21](https://github.com/cyanheads/smithsonian-mcp-server/issues/21))
- **`notice` output field** — when `contains` matches no terms, the tool returns an empty page with a `notice` explaining how to broaden or drop the filter, instead of the `no_terms` error; `no_terms` now fires only for an unfiltered empty vocabulary. ([#21](https://github.com/cyanheads/smithsonian-mcp-server/issues/21))

## Changed

- **`smithsonian_search` filtered-zero recovery** — the hint is now filter-aware: `culture`, `place`, and `date_decade` (mapped to the `list_terms` `date` field) route to `smithsonian_list_terms { field, contains: <value> }` instead of an unrelated `object_type`/`unit_code` harvest; `object_type`/`unit_code` keep the existing harvest-from-results behavior, and both combine in the hint when both kinds of filter are set on the same query. ([#21](https://github.com/cyanheads/smithsonian-mcp-server/issues/21))
- **`smithsonian_get_object` description** — no longer claims "the full catalog record," "all available metadata," or "provenance"; now describes a normalized catalog metadata projection and lists only the fields the output schema actually exposes. ([#22](https://github.com/cyanheads/smithsonian-mcp-server/issues/22))
- **`smithsonian_find_related` description** — no longer exposes internal orchestration ("up to 4 parallel searches," dedup/interleave mechanics); now describes the capability (shared metadata-signal matching, cross-museum discovery) and result semantics. ([#22](https://github.com/cyanheads/smithsonian-mcp-server/issues/22))
