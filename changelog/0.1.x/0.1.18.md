# 0.1.18 — 2026-07-22

## Added

- **`smithsonian_explore` `start`** — 0-indexed pagination offset (`start = page × rows`, max 50/page) pages the full category result set; `museum_breakdown` stays computed from the current page. Guards against the same past-the-end defect class fixed in #29/#30 from the outset: a `start` past the end returns a successful empty page (checked against the true `rowCount`, not the page-local object count), and `truncated` accounts for the offset already consumed. ([#24](https://github.com/cyanheads/smithsonian-mcp-server/issues/24))
- **`smithsonian_find_related` `signals[]`** — per-fan-out output field: `{signal, row_count, search_continuation}`. `row_count` is the signal's true uncapped upstream match count; `search_continuation` is the exact `smithsonian_search` input (`query`/`filters`) that retrieves that signal's full match set past this tool's 5,000-per-signal reach. ([#18](https://github.com/cyanheads/smithsonian-mcp-server/issues/18))
- **`enrichment.notice`** — `smithsonian_search`, `smithsonian_explore`, and `smithsonian_find_related` gain the field (already present on `smithsonian_list_terms`) and now pass explicit guidance naming the actual retrieval path (`start` for the next page; `signals[].search_continuation` for a `find_related` signal past its per-signal reach) instead of relying on the framework's generic capped-results default. ([#23](https://github.com/cyanheads/smithsonian-mcp-server/issues/23))

## Changed

- **`SmithsonianService.get()`** — new `expectedStatuses` option, forwarded to the framework's `fetchWithTimeout`. `getContent()` passes `[404]`: a missing object is a real 404 from EDAN, so a bad ID now logs at `debug` instead of `error`; the thrown `NotFound` error and its recovery hint are unchanged.
- **Vendored `skills/`** re-synced to the installed framework version (tag/changelog format, definition-analysis and field-test refinements).

## Fixed

- **`smithsonian_search`** — a `start` past the end of a real result set now returns a successful empty page instead of throwing `no_results` with spelling-correction advice; the guard checks the true upstream `rowCount`, not the page-local object count. ([#29](https://github.com/cyanheads/smithsonian-mcp-server/issues/29))
- **`smithsonian_list_terms`** — the `truncated` enrichment flag now accounts for `start`, so a past-the-end page reports `truncated: false` instead of a false positive with `shown: 0`. ([#30](https://github.com/cyanheads/smithsonian-mcp-server/issues/30))

## Dependencies

- `@cyanheads/mcp-ts-core` `^0.10.14 → ^0.10.15`
