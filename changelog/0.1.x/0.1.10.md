# 0.1.10 — 2026-07-04

## Changed

- **`smithsonian_list_terms` output** reshaped `terms` from `{value, count}` objects to a plain `string[]` — the upstream endpoint provides no per-term counts, and the tool previously errored on every call, so no working consumer received the old shape.

## Fixed

- **`smithsonian_list_terms` parses the real upstream shape** — `response.terms` is a bare `string[]`, with no per-term counts and no `rowCount`; `SmithsonianService.listTerms` now reads it directly and pages client-side, since upstream ignores `rows`/`start` and always returns the full vocabulary (`place` alone is ~114k terms). `field` enum narrowed to `unit_code, culture, place, date, online_media_type` (`object_type` is a persistent upstream WAF 403; `media_usage` a 400 identical to an unknown field). ([#7](https://github.com/cyanheads/smithsonian-mcp-server/issues/7))
- **Filter example values and zero-result recovery** — pinned `object_type`/`culture` example values corrected to Smithsonian's controlled-vocabulary forms (e.g. `Paintings`, `Aztecs` — the prior singular forms returned zero rows); `smithsonian_search` now throws `invalid_filter` instead of `no_results` when filters are present and nothing matches, with recovery pointing at `smithsonian_list_terms`. ([#8](https://github.com/cyanheads/smithsonian-mcp-server/issues/8))
- **Enrichment output-schema crash on non-truncated results** — `truncated`, `shown`, and `cap` are now `.optional()` in the enrichment block of `smithsonian_search`, `smithsonian_explore`, `smithsonian_list_terms`, and `smithsonian_find_related`; these fields are only ever written on the capped branch, so the framework's `output.extend(enrichment)` parse threw on every non-truncated result. ([#13](https://github.com/cyanheads/smithsonian-mcp-server/issues/13))

## Security

- **`js-yaml`** (transitive) `3.14.2 → 3.15.0` — fixes [GHSA-h67p-54hq-rp68](https://github.com/nodeca/js-yaml/security/advisories/GHSA-h67p-54hq-rp68) (CVE-2026-53550), a moderate-severity quadratic-complexity denial-of-service in merge-key handling via repeated aliases. `bun audit`: 1 moderate → 0.
