# 0.1.11 — 2026-07-04

## Changed

- **Tool description prose** reworded to value semantics across `smithsonian_find_related`, `smithsonian_get_media`, `smithsonian_get_object`, `smithsonian_list_terms`, and `smithsonian_search` — dropped call-order coaching and implementation-speak (`"throws Forbidden"`), and changed `find_related`'s result-merging language from "ranked list" to "interleaves results across the fan-out signals so each contributes." No schema or behavior changes. ([#12](https://github.com/cyanheads/smithsonian-mcp-server/issues/12))
- **`docs/design.md`** reconciled to as-built: added the `smithsonian_list_terms` row, corrected 8 `(InvalidParams)` cells to `(ValidationError)`, corrected the Tool Overview table's `not_cc0` cell from `(NotFound)` to `(Forbidden)`, replaced the nonexistent `online_media_type` filter with `cc0_only`, reworded the `invalid_filter` contract to "filtered search matched nothing," pluralized `object_type`/`medium` examples, and rewrote the API-Reference `fq` row — EDAN has no `fq` parameter; filters are ANDed into `q` as Lucene terms. ([#12](https://github.com/cyanheads/smithsonian-mcp-server/issues/12))
- **`CLAUDE.md`/`AGENTS.md`** synced to the current framework template (kept byte-identical) — expanded "Server instructions" into "Server identity and instructions" with the full `createApp()` identity example, and documented the `ctx.elicit.url()` form.

## Removed

- **`SMITHSONIAN_MAX_ROWS`** env var — documented but never read by any tool; each tool already carries its own default/max pair, so one shared knob was misleading. Removed from `src/config/server-config.ts`, `.env.example`, `README.md`, `docs/design.md`, and the `CLAUDE.md`/`AGENTS.md` config example and structure tree. No replacement; advertised tool schema defaults (e.g. `smithsonian_search.rows` default 20, max 100) are unchanged. ([#11](https://github.com/cyanheads/smithsonian-mcp-server/issues/11))

## Fixed

- **`materials` no longer duplicates dimension-labeled entries** — `normalizeToFull()` now excludes `physicalDescription` entries whose label marks a measurement (`Dimensions`, `Measurements`) from `materials`, via a shared `isDimensionLabel()` predicate also used to build `dimensions`. A generic `"Physical Description"` label still falls through to `materials` — no label-level signal separates material prose from measurement prose there. ([#9](https://github.com/cyanheads/smithsonian-mcp-server/issues/9))
- **`not_found` errors now carry `reason: 'not_found'` in `data`** — both `notFound()` call sites in `SmithsonianService.getContent()` pass `reason: 'not_found'`, matching the contract `smithsonian_get_object`, `smithsonian_get_media`, and `smithsonian_find_related` already declare. Wire code is `-32001` (`NotFound`). ([#10](https://github.com/cyanheads/smithsonian-mcp-server/issues/10))
