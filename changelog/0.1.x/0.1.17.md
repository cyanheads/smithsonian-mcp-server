# 0.1.17 — 2026-07-19

## Fixed

- **`not_found` recovery on `smithsonian_get_object`, `smithsonian_get_media`, `smithsonian_find_related`** — the shared `SmithsonianService.getContent()` error path now carries each tool's declared recovery hint ("Verify the ID via smithsonian_search and use the record_id from search results.") in `structuredContent.error.data.recovery.hint` and the `Recovery:` line in `content[]`, matching the other `ctx.fail()`-routed errors. `getContent()`'s `ctx` parameter widened from `RequestContextLike` to `Context` to reach `ctx.recoveryFor()`. ([#25](https://github.com/cyanheads/smithsonian-mcp-server/issues/25))
- **`smithsonian_explore` museum mode** — replaced the `length <= 8 && /^[A-Za-z]+$/` shape gate, which misrouted unit codes longer than 8 characters or containing separators (plus any human-readable museum name) to a free-text fallback whose hit count was reported as the museum's `total_count`, with a literal, case-sensitive `unit_code` filter matching the culture/period/medium modes. An unrecognized value now reaches the `no_results` error and its `smithsonian_list_terms` recovery hint instead of a silently-wrong result set — museum mode no longer accepts a free-text museum name. ([#26](https://github.com/cyanheads/smithsonian-mcp-server/issues/26))
- **`museum_name`** — the `MUSEUM_NAMES` map now resolves 44 of the 48 live `unit_code` values, up from 14 reachable of 16, sourced from the Smithsonian's own OpenAccess data dictionary and each record's `data_source`. The remaining 4 codes (`FSA`, `NASMAC`, `NMAIA`, `SAAMPAIK`) have no primary-sourced name and keep the raw-code fallback rather than a guessed one; the `museum_name` field descriptions now say so. Dropped two dead keys, `NMNH` and `FSG`, that can't match a live record. ([#27](https://github.com/cyanheads/smithsonian-mcp-server/issues/27))

## Changed

- **`smithsonian_search`'s `online_only` and `has_media` descriptions** — reworded to explain the two read different upstream signals: `online_only` matches an indexed `online_media_type` value that also covers non-visual surrogates (scanned books, finding aids, catalog cards) without deliverable media, while `has_media` — not the filter — predicts whether `smithsonian_get_media` returns anything. No code path changed. ([#28](https://github.com/cyanheads/smithsonian-mcp-server/issues/28))
- **`README.md`, `docs/design.md`** — museum-mode "or full name" wording removed to match #26's `unit_code`-only behavior; `online_only` wording aligned with #28's corrected description.
