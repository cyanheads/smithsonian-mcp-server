# 0.1.16 — 2026-07-19

## Changed

- **`smithsonian_explore` description and `sample_objects`** — replaced "curated set of sample objects" / "representative" language with an accurate description: the tool returns the first page of upstream matches in upstream order, with no curation or representativeness selection applied. Also drops "Constructs and executes a category-constrained search" (internal-mechanism phrasing) from the top-level description. ([#12](https://github.com/cyanheads/smithsonian-mcp-server/issues/12))
- **Museum unit-code examples** — corrected `"NMNH"` examples across `smithsonian_search`, `smithsonian_explore`, `smithsonian_find_related`, and `docs/design.md` to real discipline sub-unit codes (`"NMNHBIRDS"`, `"NMNHPALEO"`); the National Museum of Natural History is indexed under sub-units, not a bare `"NMNH"` — the old examples would return nothing if used as a filter value.
- **Tool description prose tightened** across `smithsonian_find_related`, `smithsonian_get_media`, `smithsonian_get_object`, and `smithsonian_list_terms` — shortened wording and dropped restated implementation mechanics (e.g. `find_related`'s `start` field description cut its page-seam-shift explanation) with no schema or behavior change.
- **`docs/design.md`** reconciled to match: the online-availability filter line, `smithsonian_search`/`smithsonian_explore` unit-code examples, and the `smithsonian_explore` description and Tool Detail prose.

## Fixed

- **`smithsonian_search` `date_decade`** — now enforces the documented `"NNNNs"` format with a Zod `.regex()` (emitted as a JSON Schema `pattern`), so a malformed value (`"1920"`, `"20s"`, `"1920S"`) is rejected at the schema boundary instead of reaching the upstream API as a zero-result query. Regression test added.
