# 0.3.2 — 2026-07-26

## Added

- **`topic` facet** — added to `smithsonian_list_terms`'s `field` enum (133,113 terms), `filters.topic` on `smithsonian_search_objects`, and a `topic` mode on `smithsonian_browse_category`. A hard indexed constraint: `topic:"Quilts"` matches 1,134 objects where the same word as free text matches 2,677. ([#44](https://github.com/cyanheads/smithsonian-mcp-server/issues/44))
- **`filters.name` on `smithsonian_search_objects`** — indexed named-party filter (maker, collector, donor, issuing authority, …), added so `smithsonian_find_related`'s hard `name:` fan-out has a reproducible `search_continuation`. Not enumerable via `smithsonian_list_terms`; the reliable source is a `smithsonian_find_related` name signal, since `smithsonian_get_object`'s `makers[]` is a differently-formatted free-text approximation of the same parties. ([#43](https://github.com/cyanheads/smithsonian-mcp-server/issues/43))

## Changed

- **`smithsonian_find_related`'s named-party signal** no longer hardcodes the label `maker` on the anchor's first `freetext.name` entry — most anchors were asserting a maker relationship the catalog never claimed (collectors, donors, issuing authorities, biogeographical regions). The signal now prefers `indexedStructured.name` as a hard `name:` filter, and otherwise walks `freetext.name[]` using each entry's own label, skipping any candidate whose value duplicates the culture filter. ([#43](https://github.com/cyanheads/smithsonian-mcp-server/issues/43))
- **`smithsonian_find_related`'s topic fan-out** switched from a free-text query to a hard `topic:` filter, carried through `search_continuation`. ([#44](https://github.com/cyanheads/smithsonian-mcp-server/issues/44))

## Fixed

- **`RawIndexedStructured.name` typed as `string | { content?: string }`**, was `string[]`. Bibliographic and archive records wrap `indexedStructured.name` entries as `{ content, … }` rather than a bare string; the new `name:` fan-out was the first consumer of the field, so roughly 2% of `smithsonian_find_related` anchors threw an unclassified `-32603` with no reason and no recovery hint.
