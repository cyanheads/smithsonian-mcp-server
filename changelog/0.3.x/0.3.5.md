# 0.3.5 — 2026-07-26

## Changed

- **`object_type`'s casing split is now documented everywhere a caller acts on it.** `filters.object_type` on `smithsonian_search_objects` and `value` on `smithsonian_browse_category` state that matching is exact and case-sensitive and that casing variants (`button` vs. `Button`) are indexed as separate categories with separate `total_count`s. The `object_type` field in search results, the harvested-value recovery hint (`composeFilterHint`), the `invalid_filter` recovery text, and `browse_category`'s `medium`-mode recovery hint (`categoryRecoveryHint`) all carry the same note. ([#50](https://github.com/cyanheads/smithsonian-mcp-server/issues/50))

## Fixed

- **`title` and `description` no longer carry raw HTML markup or undecoded character entities.** A new `toPlainText()` in `smithsonian-service.ts` strips tags (keeping their text — an `<a href>` becomes its link text) and decodes named/decimal/hex character references once, applied in the shared `normalizeToSummary`/`normalizeToFull` projection path so `smithsonian_search_objects`, `smithsonian_get_object`, `smithsonian_find_related`, and `smithsonian_browse_category` all inherit it. A legitimately bare ampersand or angle bracket in a title is left untouched. ([#49](https://github.com/cyanheads/smithsonian-mcp-server/issues/49))
- **A host-level 404 on `/search` or `/terms/{field}` now surfaces as `ServiceUnavailable` and retries with backoff, instead of a non-retryable `NotFound`.** Those are collection endpoints that exist whenever the service is up, so a 404 there — the Cloud Foundry router's `unknown_route` response when api.data.gov drops the route mapping — is never a statement about the requested resource. The reclassification happens inside `SmithsonianService`'s private `get()`, behind a new `collectionEndpoint` option passed by `search()` and `vocabulary()` (backing `listTerms()`/`describeTerm()`), so the call lands back in `withRetry`'s transient set. `getContent()`'s per-object-ID 404 is unchanged — still `not_found`, still a single attempt. ([#51](https://github.com/cyanheads/smithsonian-mcp-server/issues/51))
