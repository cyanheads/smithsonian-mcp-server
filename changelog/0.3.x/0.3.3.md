# 0.3.3 — 2026-07-26

## Fixed

- **Indexed-term recovery hints no longer route to a dead end.** When a filter value was an exact vocabulary term matching no retrievable objects, `smithsonian_search_objects` and `smithsonian_browse_category` pointed the caller at `smithsonian_list_terms { field, contains: <the failing value> }` — a `contains` search on a full term returns only that term, so the suggested call had nothing to offer. `SmithsonianService.isIndexedTerm` is now `describeTerm`, which tests derived candidate substrings (the value, the segment before its first `--`/`(`/`,`, its leading token) against the cached vocabulary and returns the first that matches a term other than the value, with a count. Both tools' recovery hints name that substring and count when one exists, and drop the substitute-term clause entirely when none does. Measured against the issue's reported `topic` value: the old route returned 1 term; the new route returns 235. ([#46](https://github.com/cyanheads/smithsonian-mcp-server/issues/46))
- **No-neighbor hint wording corrected from a false universal claim.** The dropped-clause branch asserted "no substring of it lists a different `<field>` term" — untrue, since only three fixed candidates are tried (e.g. `contains: "Yank"` does list 16 terms the untested candidates missed). Reworded to "neither the value nor a leading segment of it."

## Dependencies

- `@cyanheads/mcp-ts-core` `^0.10.16` → `^0.10.17` — restores `Timeout` (-32004) classification for fetch timeouts, which had fallen through to `ServiceUnavailable`.
