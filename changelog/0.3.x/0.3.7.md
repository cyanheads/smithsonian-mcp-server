# 0.3.7 — 2026-09-20

## Changed

- **An argument rejection is `InvalidParams` (`-32602`)**, not `ValidationError` (`-32007`). It carries `data.reason: "invalid_arguments"` and a schema-derived `data.recovery.hint`; a required field left out renders as `Missing required field` rather than as a wrong choice. A client branching on the old code needs updating.
- **Tool error text closes with `(reason <reason> · not retryable)`** whenever the error carries a reason or a boolean `retryable`, and carries the declared guidance as a trailing `Recovery:` line — dropped when the message already states it verbatim. `structuredContent.error` is unchanged.
- **Tool arguments pass a pre-validation pass before rejection** — a client-added `_`-prefixed or call-bookkeeping root key (`_meta`, `toolCallId`, `tool_call_description`) is dropped, a case-style key alias is rewritten to the declared spelling (`Field` → `field`), and a JSON-stringified array is repaired and re-parsed once. A call that still fails gets the identical rejection.
- **Stateless HTTP sessions are declared in source** as `createApp({ sessionMode: 'stateless' })`, so an install that never sets `MCP_SESSION_MODE` resolves the same way the container does.
- **Engines floor is Bun ≥ 1.4.0** (Node ≥ 24 unchanged).
- **Development skills live in `framework-skills/`**, not `skills/` — a plugin install no longer loads them as agent skills.

## Added

- **`.github/CONTRIBUTING.md` and `.github/CODE_OF_CONDUCT.md`** — where to file, which layer owns a bug, and what makes a report actionable.
- **`bun run audit:fix`** — `bun audit fix`, the first response to a transitive advisory.

## Fixed

- **Both plugin manifests deliver `SMITHSONIAN_API_KEY`.** Each shipped a literal `"your-api-key"` in `env`, which replaced whatever the user had exported. Claude Code now prompts for it through a `userConfig` option, and Codex forwards the exported value through `env_vars`.
