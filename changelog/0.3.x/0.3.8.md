# 0.3.8 — 2026-10-08

## Changed

- **Near-miss tool arguments are repaired before validation**: a numeric or boolean string for `rows`, `start`, `limit`, `cc0_only`, or `online_only`, and `null` for an optional field, which is dropped (mcp-ts-core 0.13.14); a JSON-stringified `filters` object, and an integer sent for a string field such as `id` (mcp-ts-core 0.13.9).
- **Argument rejections name the field path**, e.g. `rows: Invalid input: expected number, received boolean` (mcp-ts-core 0.13.9).
- **Tool error results carry `data.requestId`**, and their text ends with `request <id>` (mcp-ts-core 0.13.10).
- **Error data no longer carries server stack traces** (mcp-ts-core 0.13.7), **request context fields** (0.13.8), or **`rootCause`** (0.13.13).
- **Declared recovery hints are filled by the framework** (mcp-ts-core 0.13.10), so the tools and `SmithsonianService.getContent` drop their `ctx.recoveryFor` forwards and `getContent` takes `RequestContext`. The hint text callers receive is unchanged.
- **`server.json` npm entries** drop the `run start:*` package arguments and use `runtimeHint: "npx"`; the `streamable-http` entry sets `MCP_TRANSPORT_TYPE` to `http`, so a registry client launching it starts the HTTP transport.
- **Docker**: production dependencies install in a `deps` stage on the build platform, so multi-arch builds no longer run Bun under QEMU; musl-only native bindings are pruned from the image; Bun 1.4.0 → 1.4.2. The image no longer sets `MCP_FORCE_CONSOLE_LOGGING`.
- **CodeQL workflow** runs one job per language, each uploading under `/language:<language>`.
- **`.env.example`** documents HTTP resumability (`MCP_HTTP_RESUMABILITY*`), log rate limiting (`MCP_LOG_RATE_LIMIT_*`), failure-payload and LLM-interaction logging (`LOG_TOOL_FAILURE_PAYLOADS*`, `LOG_LLM_INTERACTIONS`), and per-signal OTLP endpoints for traces, metrics, and opt-in logs; the `MCP_HTTP_HOST` default reads `127.0.0.1`.
- **Ignore files**: `.gitignore` and `.dockerignore` cover every `.env*` except the committed templates (`.dockerignore` adds the MCP Registry token files), `.gitignore` stops re-including `coverage/coverage-final.json`, and `.mcpbignore` keeps `docs/idea.md`, `logs/`, `.cache/`, and `tests/` out of the bundle.
- **`package.json`** pins `packageManager` to `bun@1.4.2` and excludes `dist/*.mcpb` from the npm tarball.
- **`devcheck.config.json`** drops the `typescript` entry from the `outdated` allowlist and gains an empty `lint` block.
- **Framework scripts re-synced**: `lint:packaging` gains checks for the `dist/*.mcpb` exclusion, `manifest.json` version parity, Dockerfile build-platform stages, and the `server.json` npm launch shape; `lint:mcp`, `devcheck`, and the skill-version check are updated, and `release:github` gains `--check`.
- **`framework-skills/`** re-synced to mcp-ts-core 0.13.14.
- **`CLAUDE.md`, `AGENTS.md`, and `README.md`** carry the new framework and MCP SDK pins, the updated context and error-contract guidance, and the Bun v1.4.2 badge.

## Added

- **`scripts/install-otel.ts` and `scripts/prune-musl-packages.ts`**, run by the Dockerfile `deps` stage.
